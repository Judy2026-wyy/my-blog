## 题目

给定两个大小分别为 `m` 和 `n` 的正序（从小到大）数组 `nums1` 和 `nums2`。请你找出并返回这两个正序数组的 **中位数** 。

算法的时间复杂度应该为 `O(log (m+n))` 。

### 示例 1：

```
输入：nums1 = [1,3], nums2 = [2]
输出：2.00000
解释：合并数组 = [1,2,3] ，中位数 2
```

### 示例 2：

```
输入：nums1 = [1,2], nums2 = [3,4]
输出：2.50000
解释：合并数组 = [1,2,3,4] ，中位数 (2 + 3) / 2 = 2.5
```

---

## 第一轮提交代码

```python
class Solution:
    def findMedianSortedArrays(self, nums1: list[int], nums2: list[int]) -> float:
        i = 0
        j = 0
        merge = []
        while i < len(nums1) and j < len(nums2):
            if nums1[i] <= nums2[j]:
                merge.append(nums1[i])
                i += 1
            else:
                merge.append(nums2[j])
                j += 1
        # 剩余元素直接接上
        merge.extend(nums1[i:])
        merge.extend(nums2[j:])

        n = len(merge)
        mid = n // 2
        if n % 2 == 1:
            return merge[mid]
        else:
            return (merge[mid - 1] + merge[mid]) / 2
        
```

## 我的解题思路

<!-- 在这里写自己的思路：怎么想到的、关键步骤、时间/空间复杂度 -->
用双指针 i、j 同时从头遍历两个数组，每次把较小的那个放进 merge，直到其中一个数组走完。因为两个数组都是正序的，另一个数组剩下的元素都不小于已经合并的元素，所以直接 extend 到末尾（两行 extend 中只有一个会真正加元素，另一个是空列表）。合并完以后，按总长度的奇偶取中位数：奇数取中间那个，偶数取中间两个的平均值。

时间复杂度 O(m+n)：每个元素进入 merge 一次，每次 O(1)。


空间复杂度 O(m+n)：merge 存了全部 m+n 个元素。

### 为什么要优化

第一轮把两个数组完整合并，时间和空间都是 O(m+n)，但题目要求 **O(log(m+n))**。其实求中位数并不需要把整个数组排好，只要找到合并后**第 k 小的数**就够了。

### 优化思路：二分 + 每次丢掉 k/2 个元素

**1. 把中位数转化为「第 k 小」**

设总长度 `total = m + n`，令 `k = total // 2 + 1`：
- `total` 为奇数：中位数就是第 `k` 小。
- `total` 为偶数：中位数是第 `k - 1` 小和第 `k` 小的平均值。

例：`total = 3` 时 `k = 2`，取第 2 小；`total = 4` 时 `k = 3`，取第 2、3 小的平均值。

**2. 怎样找第 k 小：每次排除 k/2 个**

在两个数组里各往后看 `k // 2` 个元素，比较这两段的**最后一个元素** `nums1[new_i]` 和 `nums2[new_j]`：
- 如果 `nums1[new_i] <= nums2[new_j]`，那么 nums1 的这一段里，比 `nums1[new_i]` 小的元素最多只有 `(k//2 - 1) + (k//2 - 1) ≤ k - 2` 个。
- 所以 nums1 的这一段**不可能是第 k 小**，可以整段丢掉，再把 `k` 减去丢掉的个数。
- 反过来同理，丢掉 nums2 的那一段。

每一轮 k 大约减半，所以总共只需要 O(log k) = O(log(m+n)) 轮。

**3. 三个边界情况**

| 情况 | 处理 |
| --- | --- |
| 某个数组已经丢光（`i == m` 或 `j == n`） | 第 k 小直接在另一个数组里：`nums2[j + k - 1]` / `nums1[i + k - 1]` |
| `k == 1` | 返回两边剩余部分的最小值 `min(nums1[i], nums2[j])` |
| 某个数组剩下不足 `k // 2` 个 | 只取到末尾：`min(i + half, m) - 1`，k 按**实际丢掉的个数**减,另外一个就是防止越界，Min函数保证了在有效的范围内 |

**4. 不用切片，用下标 i、j 记录起点**

用 `i`、`j` 表示两个数组「还没丢掉的部分」从哪里开始，丢元素时只移动下标，不复制数组，所以额外空间是 O(1)。

### 优化后的代码

```python
from typing import List

class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        m, n = len(nums1), len(nums2)

        def get_kth(k: int) -> int:
            """在 nums1、nums2 合并后的序列中找第 k 小（k 从 1 开始）"""
            i = j = 0  # 两个数组中尚未丢掉部分的起点
            while True:
                # 边界 1：某个数组已丢光，直接在另一个数组中定位
                if i == m:
                    return nums2[j + k - 1]
                if j == n:
                    return nums1[i + k - 1]
                # 边界 2：找剩余部分中最小的
                if k == 1:
                    return min(nums1[i], nums2[j])

                # 一般情况：各取 k//2 个，不足则取到末尾
                half = k // 2
                new_i = min(i + half, m) - 1
                new_j = min(j + half, n) - 1

                # 丢掉较小的那一段，k 减去实际丢掉的个数
                if nums1[new_i] <= nums2[new_j]:
                    k -= new_i - i + 1
                    i = new_i + 1
                else:
                    k -= new_j - j + 1
                    j = new_j + 1

        total = m + n
        k = total // 2 + 1
        if total % 2 == 1: # 奇数的时候
            return float(get_kth(k))
        return (get_kth(k - 1) + get_kth(k)) / 2
```

### 复杂度对比

| 版本 | 时间复杂度 | 空间复杂度 |
| --- | --- | --- |
| 第一轮：双指针合并 | O(m+n) | O(m+n) |
| 优化：二分找第 k 小 | O(log(m+n)) | O(1) |

偶数长度时会调用两次 `get_kth`，只是常数翻倍，复杂度仍是 O(log(m+n))。

### 手动走一遍：示例 2

`nums1 = [1,2]`，`nums2 = [3,4]`，`total = 4`，所以要求第 2 小和第 3 小。

求第 3 小（`k = 3`）：
1. `half = 1`，比较 `nums1[0] = 1` 和 `nums2[0] = 3`。1 更小，丢掉 `[1]`，此时 `i = 1`，`k = 2`。
2. `half = 1`，比较 `nums1[1] = 2` 和 `nums2[0] = 3`。2 更小，丢掉 `[2]`，此时 `i = 2`，`k = 1`。
3. `i == m`，nums1 已经丢光，返回 `nums2[0 + 1 - 1] = 3`。

第 2 小同理得到 2，所以中位数是 `(2 + 3) / 2 = 2.5`。✓
